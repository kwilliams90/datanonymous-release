# Fidelity reference

This reference describes `--mode fidelity`, which retains source statistics and relationship structure for independently invented data kept locally. It is not the sharing policy. See the [sharing policy](sharing-policy.md) for the default mode.

Use the synthetic copy in a skill's documents or a synthetic-data folder. A model can then design and test code against it, and people run that code on the real data outside the model harness.

Formats: CSV/TSV/TXT (also compressed as `.gz`, `.zip`, `.bz2` or `.xz`), Excel `.xlsx`/`.xlsm` and `.xls` (written as `.xlsx`; macros are not copied), "Excel" `.xls` exports that are really HTML or delimited text (written back the same way), Parquet, Feather, Stata `.dta`, flat JSON and JSON lines, and SAS `.sas7bdat`/`.xpt` (read only; written as Parquet). Columns holding nested, list, struct or binary values are never generated or stringified: the file FAILs with the fix (`--null COL` keeps the column empty, `--exclude COL` drops it).

## Install

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e .[dev]      # Windows; on macOS/Linux use .venv/bin/python
```

Python 3.12 or newer.

## Quick start

```bash
datanonymous inspect example-data --mode fidelity                     # preview detection; writes nothing
datanonymous example-data --mode fidelity --out-dir example-output/synthetic --report-dir example-output/report --seed 1
```

`python -m datanonymous ...` works the same way. `run` is the default command, so `datanonymous run INPUT ...` and `datanonymous INPUT ...` are equivalent.

INPUT is a file or a directory. A directory is walked recursively and its subfolder tree is mirrored in the out dir (a linked folder, symlink or junction, is followed like a real one; a link back to a folder above it is a loop and is skipped). Supported tabular files are anonymised; every other file is **not copied** and is listed as skipped in the report. A `.txt` file whose first line reads like a sentence (a readme, notes) is not a table: it is skipped too.

Every tabular file needs a **header row** (the column names on the first line). A file whose first line looks like a data record (an e-mail address, an SSN, phone or date, a long or zero-padded number, values that repeat in their own column, or a cell that names no recognisable column and looks like one more value of its column in any letter case, such as a headerless list of names, unless another cell is a recognisable column name above numbers, dates, codes or e-mails, or a known word that names nobody, such as `Kid` or `Mentor`, above a column of known given names or surnames that does not hold it, unless the line also holds a cell that looks like one more ID or code of its column) FAILs with the fix "add a header row", because the header is written to the output as it is. A cell whose number of words no value of its column has (10 or more values) is no value of that column either: one word, such as `Recipient` above full names, or a phrase with a column-name word and no given name or surname, such as `Absent Teacher` above one-word surnames, unless another cell of the line is a value of its column or one more ID, code or number of it. A header made of words outside that vocabulary, or of words that are also given names or surnames, above names of the same number of words (`Reader,Listener` above given names), cannot be told from the names of a first record and FAILs the same way. `--header-row 1` asserts that the first line of a text file is its header row and skips this check. A note of 1-3 lines below the data of a CSV/TSV/TXT file that does not split like the records (a line with a letter, or a rule of symbols such as `-----`, without quote characters, that holds the delimiter only as text punctuation followed by a space, in a file whose values never start with a space: `Report generated by Skyward on Monday, October 3, 2025 2:15 PM`) is no data row: like an Excel footer row it is written back in place as same-shape placeholder text (`--keep-titles`: verbatim, and then screened like a title row), and the read code in `DATA_DICTIONARY.md` stops after the last data row (`n_max` / `nrows`).

Headers, sheet names and paths are written exactly as they are (scripts depend on them), so they must not hold personal data. Every column header (the CSV/TSV/TXT header row, Excel header cells, Parquet/Feather field names and struct fields, Stata variable names, JSON keys), every Excel sheet name and every file and folder name of the mirrored path is screened, as written and URL-decoded (`Kaden%20Yazzie`), for personal data (with `--keep-titles`, so are the title and notes rows written verbatim). Unlike values (step 6), these names cannot be replaced by pseudonyms, so they are judged by their content: an e-mail address, phone number, SSN or street address in it (a URL alone is no personal data; 10 bare digits count as a phone number after a phone word, or as a valid North American number that does not follow a numbered thing such as `Extract_` or `PO`, also standing alone: a JSON key, file, sheet or folder named `3125550187`; names and values share one shape test, but a number, a month and a year joined by underscores or spaces is no SSN in a name, `Bus_Route_214_12_2024`, nor is a school year beside a short number a phone number, `Grades_2024-25_612345`); a person's name, meaning a known given name next to a known surname, neither of them an everyday word (`Garcia_Ana`, `Ana Garcia`, `AnaGarcia`, `Smith_John_IEP.csv`, also names of newcomer families on the lists such as `Hodan Warsame`), or a name written as `Smith, John`, `Okafor, Summer`, `Adeyemi, Oluwaseun`, `Park, Jennifer`, `Smith, J.`, `J. Smith`, `Smith J.`, `Smith_J`, `Jayden M.`, a user name (`jgarcia`, `j.garcia`), a title or role before a name (`Mr. Smith`, `Ms. Garcia`, `Sr. Garcia`, `Herr Schmidt`, `Counselor Nwosu`, `Mrs. G`); or a real ID of the run (a pivoted table with one column per student, also without a separator: `score482913`; a per-student file named by the one ID it holds: `IEP_496487.csv`; a number labelled as a person's, however many IDs the run has: `Student 612587`, `Student Number 612587`, `612587_IEP_Goals.csv`, a file `iep/1053.csv` or a sheet `1053` of `iep_progress.xlsx`; a number with a person or document label elsewhere in the name when at most one number in a hundred of its length is a real ID: `Student_Schedule_612714.csv`, `IEP_Progress_Report_612714.pdf`; a school year is never one, `IEP_Caseload_2425`, `2425_Student_Roster.csv`, and a date beside a label only when few dates written that way are real IDs and its siblings are not all dates, `101524_Student_Attendance.csv` in a folder of daily exports; a zero-padded ID such as `Goals_059295.csv`, unless the run's names also hold zero-padded numbers of that width that are no ID, such as county-district numbers `015901_Alamo_Heights_ISD_TAPR.csv`). A number that equals a real ID only by chance (a time stamp `152233`, a daily file `Attendance_1001`, `Report_153017`, `Room_10101`, `CIP_150301`, many IDs of the same length, a room number among sequential student numbers) needs repeated evidence: sibling names that share the same text around distinct real IDs (`Progress_Report_612714.pdf`, `Case_612714_Notes.csv` and others like them; one column, sheet, file or folder per student `1014`, `1036`, `score1014` ...: two or more of them that are real IDs of one ID namespace fail however many numbers of their length are real IDs, also beside a few numbers that are no ID such as withdrawn students' columns (at most one of them, or a quarter of the set), unless they all read as dates, school years or clock times, count up in one constant step, follow a numbered word such as `Q`, `Item` or `Room`, or the folder or workbook says what they are and they lie among dense real IDs: `rooms/`, `enrollment_by_zip.xlsx`; the text around the numbers may differ in initials, `FK (1004)`, `GB (1023)`, or, from three real IDs on, in whole words, `Garcia (1004)`, `Nguyen (1023)`, `Okafor (1293)`), or several such names across the run (per-student documents one per folder: `transcripts/Transcript_612714.pdf`, `behavior/BIP_737720.pdf`). Single words (`Grant`, `Rose`, `Hall`, `May`, campus and county names such as `Crockett`, `Lamar`, `Travis`), header words (`First_Name`, `Max_Date`, `Student Name`), the names of schools, buildings and places (`Lincoln High`, `Martin Luther King Jr Elementary`, `Victor H Hexter ES`, `Gus Garcia YMLA`, `Smith Hall`, `Fort Worth`, `Oak Hill`, `Columbus, Georgia`) and public names pass: schools, programs, federal funds and awards named after notable people (`Rosa_Parks`, `Sam_Houston`, `Cesar Chavez`, `Carl D. Perkins CTE`, `KIPP_Austin`, `Green_Dot`, `Cal_Grant`), authors, characters, historical figures and eponyms of curriculum units (`Harry Potter Ch 1-5`, `Atticus Finch Essay`, `Gary Soto Seventh Grade Quiz`, `Charles's Law Lab`, `Lewis Dot Structures`), court cases (`Morse v. Frederick`), vendors (`Sherwin Williams`, `Dell Latitude`) and 10-digit time stamps (`roster_1696342522`). A match FAILs the file, and a flagged folder fails every file under it; nothing is renamed. A name that holds a flagged name, also with its words in another order, as its given name and surname alone or the flagged name of a folder of the input path, fails too (`Mark_Patel_Walkthrough.csv` beside a folder `Patel, Mark` or `Mark A. Patel`; `Summer_Davis_Walkthrough.csv` beside a folder `Davis, Summer Joy`; `Davis_Summer_Reading_Log.csv` in an input folder `Davis, Summer`). The fix: rename the column, sheet, file or folder in the source or reshape the table to one row per person, or skip the file with `--exclude-path GLOB` (`--exclude COL` matches a column by its name only, not by position). `--keep-name TEXT` keeps a flagged name that is not personal data. The flagged name itself is never printed: the console, the report, the manifest and the out-dir docs show it as `[redacted-N]` and locate it by column number (`column 7 of 12`), sheet number, or the file's or folder's place in its parent folder. Names the run only prints are redacted the same way without failing anything: the folders of the input, out-dir, report-dir and `--config` paths, column and sheet references typed in the settings, names quoted by a read error and values a usage error repeats. Office owner and lock files (`~$Roster.xlsx`) are skipped. **What D34 does not catch:** the name screen is a best-effort layer. Unusual names (names that are everyday words such as `Summer Davis` or `Joy Taylor`, names outside the name lists, names in non-Latin scripts) in file, sheet or folder names or in one-column-per-student headers may pass, and so may one column, sheet, file or folder per student named by a single given name or surname (`Aaliyah`, `Okafor`) and per-student folder trees (`Garcia/Ana/`); so may a single document named by a real ID after a word that is no person or document label (`Transcript_612714.pdf` alone, among thousands of IDs of its length), or with such a label elsewhere in its name where more than one number in a hundred of its length is a real ID (`Student_Schedule_612714.pdf` among 50,000 six-digit IDs), or whose ID reads as a date or a school year beside its label (`IEP_Meeting_101524.pdf`, `2425_IEP.pdf`), and one column, sheet, file or folder per student whose IDs all read as dates, school years or clock times (student numbers given by entry year that read as `YYYYMMDD` dates, `20241015`), count up in one step, or lie among dense student numbers under a folder or workbook whose name says they are something else (`Rooms/`). The other way round, sibling names that are real IDs FAIL whatever they really are, since headers that are IDs are rare: a table or workbook with one column or sheet per room, course, bus route, ZIP code or score cut point whose numbers are real student numbers (rooms `1104`, `1203`, `2110` among students numbered 1001-2500; a pair is enough) FAILs unless they count up in one step or its folder or workbook name says what they are (`Rooms/`, `enrollment_by_zip.xlsx`); `--keep-name TEXT` keeps such names, one per name (a `keep_name:` list in `--config` keeps a whole set). Check per-student file trees and pivoted layouts (one column or sheet per student) before sharing the output; `--keep-name TEXT` keeps a flagged name that is a false positive.

## What you get

**Out dir** (`--out-dir`, required): only synthetic files plus documentation computed from the synthetic data.

- each synthetic file at the same relative path and file name as its source (a real `.xls` is written as `.xlsx`, SAS files as `.parquet`);
- `README.md`: what is and is not preserved;
- `DATA_DICTIONARY.md`: per column the type, R class, readr letter, pandas dtype, missing-value tokens, levels as written (the real ones kept and the pseudonyms of the others, with their count) or a numeric summary (level counts below `--min-cell` shown as `<10`), plus ready-to-paste `readr` and `pandas` read calls;
- `schema.json`: the same, machine-readable.

If one of these doc names collides with a synthetic file, the doc is written with a `_datanonymous_` prefix (added again if that name is taken too). A doc never overwrites a data file.

**Report dir** (`--report-dir`, default `<out-dir>-report` next to the out dir): aggregates only, never a real ID, name, email, phone, address or free-text value.

- `REPORT.md` and `report.json`: totals, a status table (PASS / WARN / FAIL per file), skipped files, failures with the exact fix, warnings;
- `manifest.json`: seed, tool and library versions, settings, source-to-output file map;
- `files/<relative path>.md` and `.json`: per column real vs synthetic statistics, detected type and reason, adjusted flags, fidelity verdict, IDs and within-ID constants, missingness patterns, chance-match results and the self-check.

Keep the report dir out of anything you share: it describes the real data (in aggregate).

## How it works

1. **Read** every value as the exact raw string (no type guessing, no missing-value conversion), keeping encoding, byte-order mark, delimiter, quoting, line endings and the raw header. The delimiter is the one of comma, tab, pipe and semicolon that splits every line into the same number of fields; when several do, the quoting decides, then punctuation (a comma followed by a space, as in `Smith, Jane`, is text), then the character least common in text, and the file gets a warning to confirm the columns with `--delimiter`.
2. **Detect** each column's type with a fixed, ordered set of rules on its distinct values: empty, constant, single-token flag, boolean, ordinal vocabularies (grade levels, letter grades, Likert, year of study, parental education ...), school years, leading-zero codes, integers (discrete or continuous), 4-digit years, decimals, organisational codes, factors (up to `--factor-max` distinct values, default 20), and non-factor text. Organisational codes keep their real values whatever their count (except personal-data shapes and person names inside them, step 6): the header is a school/site/campus/building/course/section/term/district/exit code/entry code/ELL code word, optionally followed by `id`, `code`, `name`, `number`, `desc` ... (`SchoolID`, `course_name`, `section_number`); `Section_Teacher` or `School_Counselor` are not codes. Known codes that cannot identify a student are organisational codes too (any case and separators): NCES school and district IDs (`NCES`, `NCESSCH`, `NCES_SCH_ID`, `School_NCES_ID`, `NCES School ID`, `NCES_ID`, `LEAID`, `LEA_ID`, `SCHID`, `ST_SCHID`, `ST_LEAID`), California CDS codes (`CDS`, `CDS Code`, `CDSCode`, `County_District_School_Code`), Texas county-district-campus numbers (`CDC`, `County-District-Campus Number`, `County_District`; `Campus Number` and `District Number` already are), general-ledger account codes (`GL_Account`, `GL Account Number`, `Account Code`, `Acct_Cd`), course reference numbers (`CRN`, `Term_CRN`, `Course Reference Number`) and ISBNs (`ISBN`, `ISBN13`, `ISBN-10`, `Textbook_ISBN`); the finance segments `Fund`, `Function` and `Object` (also `Fund_Code`, `Obj_Cd`) only when every value is a code (digits of one width of two or more, or digit groups joined by dashes, spaces or two or more dots), so a text `Function` or a `Fund` of amounts stays what it is. A bare `Account` or `Account_Number` is not one (a lunch, fee or library account number is a person's), nor are census tracts and `GEOID` (where a student lives), provider `NPI`s (a person's ID) and `Barcode` (it may be a student ID card). An organisational code is never split into list items at its commas (`ALG1-03 Garcia, Ana` is one code). Columns named like personal data never keep their real values: first/last/full name (also name parts after a person word: `Student_First`, `stu_last_nm`, `Guardian1First`, `LastFirst`), any `..._name` that is not a school/course/program ... name (`Mother_Name`), a person role (`Teacher`, `Counselor`, `Advisor`, `Guardian`, `EmergencyContact`, `Section_Teacher`), also numbered, ranked or plural (`Guardian1`, `Contact #2`, `Parent(s)`, `Guardian_Primary`, `Teacher_of_Record`, `Name_2`), the person who did something (`Referred_By`, `Entered_By`), email, phone (`Phone`, `Home_Phone`, `Parent_Cell`, `Tel_No`, `Mobile`, `Fax`, `WhatsApp`, `SMS_Number`; a column named `SMS`, `Text`, `Home`, `Work` or `Primary` becomes a phone column when its values are phone numbers), address, city, date of birth, and notes/comments. Values are never judged by their content (names, sentences): which real values a column may write is decided by the allowlist of step 6.
3. **IDs**: columns named like a person/record ID (`id`, `student_id`, `studentnumber`, `stateid`, `localid`, `lasid`, `upn`, `dcid`, `personid`, `staffid` ... or `--id-col`), state student-ID acronyms (`NYSSIS`, `OSIS`, `STN`, `UIC`, `WISEid`, `SUNS`, `FLEID`, `KSID`, `MOSIS`, `PAsecureID`, `EDUID`, alone or with an ID word, `NYSSIS_ID`, `STN Number`, and the systems that name one with an ID word: `EIS ID`, `EMIS ID`, `KIDS ID`, `MARSS ID`, `SAIS ID`, `MSIS ID`, `PEIMS ID`, `TSDS ID`; any letter case, with separators, after a student word or an ID qualifier too: `Student NYSSIS`, `Old_STN`; `--no-default-ids` turns the name list off, and a bare student-ID code such as `NYSSIS` or `SSID` is then an ID column only when its values are ID-like keys), and any header that pairs a person word (student, pupil, learner, child, staff, family, teacher, employee, person, guardian, parent) with an ID word (id, number, no, key ...) such as `Family_ID` or `Guardian_Number` (a bracketed or dashed qualifier such as `Student ID (Aeries)` or `Student ID - District` does not hide the ID word), get new IDs of the same shape (digits, zero padding, letter prefix, case, punctuation) that never equal a real one. Each real ID becomes exactly one synthetic ID with exactly its number of rows, consistently across every file of the run (a plain `id` column links only within its own file). Row numbers stay as they are: a column holding each of 1..n exactly once keeps 1..n, and so do the same IDs in the other files of the run. When the IDs are so dense that there are too few unused values with the same number of digits (for example 1..2000 with one row deleted), some synthetic IDs get a different number of digits, with a warning. This happens only for IDs written as plain integers: a zero-padded ID (`0012345`) keeps its width, and the file FAILs if that width has no room. A cell of an ID column without a letter or digit (`-`, `?`, `***`) names no one and is written as it is. Synthetic IDs are assigned at random (a sorted file is re-sorted on the new IDs), so the real order cannot be used to match them back. Fail-safe for headers outside these forms: a header with a student word (`Student_SK`, `Student PIN`, `Stu`, `Student (District)`) or a student-ID code (`CALPADS SSID`) whose values are ID-like keys (numbers of three or more digits or codes with digits, a few placeholders such as `TBD` allowed, integers stored as `100234.0` included) is an ID column too, unless the header names a measure (`Student_Count`, `Cost per Student`); so is a header ending in an ID word (`Admission No`, `Lunch Number`, `Aeries ID`, `Other ID`) over such keys, however few, with a warning, when the table has no ID of the student (room, bus and item numbers of three or more digits cannot be told from a small school's admission numbers by their values: the warning names `--org-code` to keep them). Other values on up to a fifth of the rows (`TBD`, a warehouse's unknown member `-1`, `100234, 100567`, `100234?`) never stop such a column from being an ID column; they get same-shape codes too. Beside a student ID, such a column is an ID column only when most of its keys are each held by fewer than `--min-cell` students (a state ID, a lunch number, a sibling's ID), not when `--min-cell` or more students share them (a test, a bus, a class). `--org-code COL` keeps the real values; `--person-id COL` (when it numbers the row's own person) or `--id-col COL` (records or other people) confirms the ID without the warning. Other columns that look like IDs get a warning: UUIDs, 32/40/64-character hex hashes, unique sequential numbers, unique values under an ID-like header (`Badge_No` ...), unique fixed-width codes or numbers, codes that are almost all unique with one shape (`AB-1234`), and keys of eight or more digits repeated on several rows under a header that names no ID, measure, count or flag (a state student ID under a header the tool does not know: in a table with no ID of the student its keys also count who holds a value, step 6). Their real values are written (or replaced by labels) unless you name them with `--id-col` / `--person-id`, and the report does not list them. **Unrecognised wide keys fail their file:** in a table with no recognised ID column (none by name, by header and values, by the key discovery below or by a flag; an `--exclude`d or `--null`ed one does not count, since it is not written), such a column of repeated keys of eight or more digits FAILs its file, because they may be people's IDs or school and district codes and the values cannot tell which; the file is flagged and skipped rather than written on a chance threshold, and the other files are still written. The known non-person codes of step 2 (`NCESSCH`, `LEA_ID`, `CDS Code`, `CDC`, `GL_Account`, `Account Code`, `Fund`, `CRN`, `ISBN` ...) are organisational codes and never do; census tracts (`GEOID`), `NPI`, `Barcode` and a bare `Account` still do. The fix names the column: `--person-id COL` (or `--id-col COL`) if it is a person ID (synthetic IDs, and its real IDs count as real IDs of the run below), `--org-code COL` if it is a school or district code (its real values are kept by your choice; the report still does not list them, and its keys still count who holds a value). `--exclude COL` and `--null COL` settle it too. `--force-type COL=TYPE` and `--force-factor COL` are your explicit decision as well: the file is written, with a `d38_flagged_keys` warning on every run, since real values are written where that type writes them (`--force-type COL=IDENTIFIER` is an ID flag). Beside an ID column such a column only gets the warning above. Wide repeated keys that are no person IDs FAIL this way too in a table with no ID column when their header is not a known code of step 2, for example census tracts under `GEOID`, barcodes, Unix times under `Batch`, amounts in cents under `Encumbrance`, or 11-digit term-and-section keys under `Class` or `Offering`: name them with `--org-code COL` (or `org_code:` in `--config`). Organisational-code headers (`School`, `SchoolID`, `Campus`, `District`, `Section`), measures and counts (`Amount`, `Budget`, `Num_Visits`), dates (`YYYYMMDD` integers, Unix times under a date or time header) and phone numbers under a phone or contact header (`Phone`, `Home`, `Contact`) never fail this way; phone numbers under a header the tool does not know do, and the fix then also names `--pii-col COL=phone`. A column whose values are the IDs of an ID column of the run under another name (in another file, another sheet or its own table: `subject_ref`, `mentor`) is treated as an ID column too, with a warning: it gets synthetic IDs from that column's mapping, so its real values are never written and joins are kept (`--force-type` or `--force-factor` keep the column's own type if it does not hold person IDs). An ID column that `--exclude`, `--null` or a `--force-...` / `--pii-col` / `--org-code` flag turns into something else (with `--exclude` and `--null` also one found by its header and values, `Student_SK`) still holds real IDs: no synthetic ID equals one, the header, path and leak checks still look for them, and a column holding them is still treated as an ID column. Columns that are constant within an ID (gender, race, birth date ...) stay constant within the synthetic ID, and their levels and blanks keep their row counts as well as their counts of IDs (a value held by short ID blocks in the source is not spread onto long ones; a real value held by fewer than `--min-cell` IDs is not matched to block sizes, while a pseudonym of step 6 is, since it names no one). Numbers and dates do the same by ranges of values that each hold at least `--min-cell` IDs, and the report judges both the one-value-per-ID distribution and the written rows. Several ID columns of one person (`student_id` + `state_id` + `student_number`) stay 1:1, IDs nested in another (students in a `family_ident`) stay nested, and the same ID written `0012345` in one file and `12345` in another stays one person, each file keeping its own width. Hex IDs keep hex digits; `--id-check luhn` gives synthetic digit IDs a valid Luhn check digit when every real ID has one. A letter prefix is kept only when every ID of the column has it, and a prefix of two or more letters only when at least `--min-cell` IDs share it and it is neither a name nor a real ID (`STU0001` keeps `STU`; usernames such as `jsmith23` keep at most their first letter, never a real username). IDs that are e-mail addresses (`student_id` or `--id-col` holding `jsmith@district.edu`) get e-mail addresses built from synthetic names on example.org / .com / .net, one per real address and the same in every file, never with a real local part, username or domain. No synthetic ID equals any other real text of the run that the run does not write either (a pseudonymised label, a value of an `--exclude`d or `--null`ed column ...); an ID shape too small to avoid them all FAILs its files. A real person ID never reaches the output through another column either, whatever the reference detection above concluded: a value a column would write as it is (a category level, an organisational code, a number, including the exact minimum or maximum, a token among numbers, a list item, an `--na-value` token) that equals a real ID of the run (of any ID column of any file, also one that `--exclude`, `--null` or another flag turned into something else; at least 4 characters with a digit, compared like IDs: case, punctuation and leading zeros ignored, numbers by value; row numbers 1..n are no person IDs, and neither is a plain number in a range where most numbers of its length are real IDs, judged by the chance rule of the header and path check above, so sequential 4-digit staff numbers 1001-1350 or record numbers 1..5000 with a few gaps never turn an ordinary scale score or Lexile into an ID, while a letter-prefixed or zero-padded ID always counts) is written as a consistent same-shape pseudonym with its exact count (step 6; a level of a discrete number column gets a number of the column's format inside its range), or, in a continuous number column, as another value drawn from the column's own distribution, with a `real_id_values` warning, and a number column holding one has its value statistics left out of the report. Dates, years, school years, ZIP codes, states, booleans and coordinates are what their type says and are not compared, and `--force-factor COL` keeps every real value (the explicit opt-in).
4. **Generate** every other column independently: exact counts for categories, booleans, ordered levels and discrete integers (every level present in the source appears, a pseudonymised one under its pseudonym, step 6); interpolated values inside the observed range for continuous numbers, with the exact minimum and maximum present; invented labels (`career_aspiration_07`) or filler text for non-factor text (an e-mail address, web address or domain, phone number, SSN, IP or street address inside the text follows the same rules as those columns below, so e-mails stay on example.org / .com / .net and phones use ordinary exchanges while excluding every source phone base). Personal data gets fake values of the same shape and frequency profile: names and city names from Faker (version pinned and recorded; a synthetic full name, or the first and last name on one row, never spells a real person's full name found anywhere in the run, single-word names included), e-mail addresses built from the synthetic names on example.org / .com / .net, phone numbers in the source layout with ordinary exchanges, preserving common area-code shares while excluding every source phone base (including alternate formatting, Unicode decimal digits, country-code-1 and extension variants), SSNs in the invalid 900-999 area range, street addresses from Faker street names with the source's suffixes and unit forms, IP addresses in documentation ranges; ZIP codes held by at least `--min-cell` people (counted as in step 6, so one student's code on many rows is one holder; rows in a table without an ID) are kept and rarer ones replaced. No generated text (a fake name, e-mail or street address, a city, filler text, an invented label, a pseudonym, a rebuilt value) is a real text value of the run that the run does not write as it is, in any column or file: a person's name, address or free text, a label pseudonymised elsewhere, text a date column replaced, a value of an `--exclude`d or `--null`ed column (dropping a column does not free its values for reuse), or text outside the tables (Excel and HTML title, notes, footer and side-note text, HTML comments, free-form Parquet/Feather metadata, Stata variable and data labels); nor does a synthetic full name, or the first and last name on one row, spell one of up to five words (or two neighbouring name words of a longer title or note), nor does a synthetic e-mail address or ID have the local part (a username) of a real address or e-mail ID of the run, wherever it is held. Values the run writes as they are (kept levels, NA tokens) are public anyway, and values without a letter (numbers, dates, codes) are no text: phone numbers, SSNs and IDs have their own run-wide rules. The leak scan checks every text column of the output against these values. Formatted numbers (`$1,234.50`, `($25.00)`, `56.1%`) keep their template, numbers mixed with suppression tokens (`*`, `<10`, `n<10`) keep each token at its exact rate, and a decimal comma (`1.234,50`) is read as a number only with `--decimal ,`. Dates, datetimes, year-months, times and durations are recognised in their exact text form (ISO, `3/5/2024` or `03/05/2024`, day-first, two-digit years, `15MAR2024`, `14-AUG-24`, `Mar 5, 2024`, AM/PM, offsets and zone names, `26:15:00`, `PT1H30M`, `YYYYMMDD` integers, and Excel serial or Unix epoch numbers when the header says date/time, but is not an entry/exit code, or with `--date-cols`) and written back in that same form (values with UTC offsets keep their local times, and when the offsets follow one time zone's daylight-saving changes, as in a Parquet/Feather timestamp column with a named zone or text offsets such as `-06:00`/`-05:00` or `CST`/`CDT`, each value gets that zone's offset for its date); when day and month order cannot be told apart, month-first is assumed with a warning (`--dayfirst COL`), and `--date-format COL=FMT` names the format. Values are interpolated between the observed minimum and maximum (both present), never on a weekday that does not occur in the source; a column with at least `--min-cell` rows per distinct date (an attendance calendar), or named with `--calendar COL`, uses only its observed dates, which birth dates never do. Sentinel dates (`1/1/1900`, `12/31/9999`, `0/0/0` and the other zero days of common date systems, which no person's real date is: Excel's day 0 `12/30/1899` or `12/31/1899`, `1/1/1904`, SQL Server's `1/1/1753`, `1/1/0001`; always, also in a birth-date column, as dates: with a time of day, the way Access, Excel, SQL Server or .NET write a bare time such as `12/30/1899 9:09 AM` under `Time_In`, a zero day is an ordinary value; and a value at least 50 years from the rest held by at least 1% of the rows and by at least `--min-cell` people, such as a `12/31/2099` "still enrolled" date, but never in a birth-date column) are written back verbatim at their exact rates (a far-off date fewer people hold, such as an adult learner's birth date or a typo, is an ordinary date: only the exact minimum or maximum is written as it is), and so are the few other entries of a date column that are known placeholders (`TBD`, `Unknown`, `Not enrolled`, `N/A`, `-`; `--na-value TOKEN` keeps another one) or impossible dates (`02/30/2024`); anything else there (names and other words, free text, ID or phone numbers, e-mail addresses) gets a generated date instead and is never copied. Whole-row patterns of missing values are kept, and missing-value tokens (`NA`, blanks ...) are written back verbatim at their exact rates.
5. **Structure** that holds in every source row is kept: a code and its name (`school_id` -> `school_name`: the name is rebuilt from the synthetic code; a personal name stays consistent per code but is synthetic), values built from other columns (`email = first.last.id@domain` is rebuilt from the synthetic name and ID on example.org / .com / .net), no repeated (ID, date), (ID, course) or (ID, course, term) combinations, and IDs shared by several files (join rates and orphan rows come out the same). Rows are put in the source's sort order (up to 3 sort keys, missing values first or last), and the number of exact duplicate rows is reproduced. `inspect` and the report list each one. Rules such as `KCSE <= Yr_JoinCampus` are only suggested in the report; declare them under `rules:` in `--config` to apply them. A declared rule never changes the higher column's own values (its range, exact minimum and maximum, levels and date formats stay as generated): it decides which row gets which value, keeping the observed gaps where it can. Only a row whose lower value is above every value of the higher column gets a value past its maximum, with a warning. Panels (attendance by date), yearly snapshots and aggregate tables are detected and warned about: their time structure is not modelled.
6. **Protect**: a synthetic row (or ID) that equals a real one on every comparable column is changed by swapping cells between synthetic rows (column totals unchanged). A real text value is written as it is only when it is provably safe: booleans and numbers follow their own rules; organisational codes keep their values, except values with a personal-data shape and the person names inside them (both below); a word of the built-in vocabularies is kept whatever its count (the standard education vocabulary: race/ethnicity, gender, grade levels, ELL/SPED/504/free-reduced statuses, yes/no, terms, attendance and enrollment codes, common programs, subjects, military-connected statuses, discipline categories, home languages, regions and NCES locales such as `Eastern`, `Coast`, `Rural`, `City: Large`; plus Likert and other ordinal scales, school years, NA and suppression tokens; matched ignoring case and spacing); a value without a single letter or digit (`✓`, `✗`, `+`, an emoji) is kept too, since it names no one; any other value is kept when at least `--min-cell` (10) distinct people hold it and it has no e-mail, phone, SSN, URL or street-address shape. These shapes never depend on the column's header (an organisational code only widens them, below), and they are broad on purpose (a false alarm only costs a pseudonym): an e-mail address in any script (`josé@school.org`, `张伟@school.org`), a phone number in any national layout (`020 7946 0958`, `(020) 7946 0958`, `07911 123456`, `01 23 45 67 89`, `030 1234567`: two or more digit groups with 9-15 digits, a leading trunk 0 not counted, that are no date, year, time, decimal number, range, count, ZIP+4 code, IP address or amount), and a bare 10-digit North American number (`3125550187`, `+13125550187`, area code and exchange 2-9, so not a Unix time or the sentinel `9999999999`) is a phone number in any text value (category, constant, code or list item), whatever the column is called. Declaring a missing value is no permission to publish it: an `--na-value` token (in any column, also a date column's placeholder) is kept as it is only when it is missing-value vocabulary (`NA`, `N/A`, `Unknown`, `Missing` ...), a short number or a symbol, or when at least `--min-cell` people hold it and it has no personal-data shape; otherwise it is written as one consistent pseudonym, which stays a missing-value token of the column (the docs' `readr` and `pandas` calls list it; the report shows `[pseudonymized NA token N]`). People are counted in each table as the fewest holders any of its keys shows: every ID column (a record ID such as `DCID` or `--id-col Incident_ID`, or a teacher, staff or section number, does not turn one student's rows into many holders; beside an ID of the row's own person, other people's IDs such as a teacher, staff or guardian number do not count at all, so one teacher of a whole class does not make the class one holder; a blank ID is no new person), an ID column that `--exclude`, `--null` or a `--force-...` flag turned into something else (its real IDs still tell who is who), in a table with no ID of the row's own person a column of repeated keys of eight or more digits (step 3), and the person-name and e-mail columns of the row's own person (`Student_Name`, not `Teacher`; left out when the person's own ID already gives every ID one name, so namesakes are not merged); a table without any of these counts its rows, a record exported several times counting once. Only an ID or a name of the row's own person proves that the holders are people: for a column name found in several files the most people any of them shows decides, and a file whose keys are records, rows or other people's IDs never outweighs one that counts people. An ID proves its people by its header (`Student_ID`, `LASID`, `Perm ID`, also a student-ID header found by its values, such as `Student_SK`, `Stu` or `CALPADS SSID` ..., with or without `--person-id`): one that only `--person-id` calls the row's own person (use `--id-col` for incident, record or staff numbers) counts people only where no such file counts the value, and then the fewest any of them shows decides; a bare `SID` numbers records (sessions and visits are SIDs too) unless a name or e-mail column of the row's own person matches it one to one or its values are the student IDs of such a file (a dense, row-number-like range of numbers matches by chance and is no proof). A code table (one row per code) follows the table that uses its codes, under the same column name or another one (`programs.csv::Code` and `enrollments.csv::Program_Code`), so joins on the codes keep matching. Words of the vocabulary that are also common names (`White`, `Summer`, `Major`, `English`, `Holiday`, `Sunday`), and codes that are surnames in an all-caps export (`AN`, `TU`, `MENA`), count as vocabulary only beside an unambiguous word of their kind with at least two letters in the same column (`Asian`, `Fall`; room numbers and single letters vouch for nothing); a code of two to four capitals counts only in one case (`GT`, not `Gt`), and a phrase written as one word only with a digit or at least six letters (`EconDis`, `Grade9`; not `Daya`); a long bare number (7 or more digits) is no number kept for free. Everything else (a rare label, name or sentence, any value with personal data inside) gets a consistent same-shape pseudonym: the same length, word pattern, case, punctuation and digit pattern (`Rift Valley` -> `Duis Tempor`), with its exact count, the same pseudonym in every column and file of the run (equal columns stay equal and joins on pseudonymised values still match), never equal to a real value of the run nor a vocabulary code, drawn from the seed (not from a hash of the value). This covers category, constant and flag levels, ordered-dictionary entries and Stata value labels, multi-select items (rewritten inside each combination; a multi-select written as whole combinations, at most `--factor-max` of them, also keeps a combination of kept items only when at least `--min-cell` people hold it or all its items are vocabulary words, so two common halves never rebuild a rare whole value such as a `Last, First` name, and the pseudonym of such a combination keeps its vocabulary items), tokens among numbers, and the dependent of a code -> name structure; an e-mail, phone, SSN, URL or address inside a pseudonym follows the rules of those columns (example.org, ordinary phone numbers excluding every source phone base ...). The report never prints a pseudonymised value: both sides show `[pseudonymized N]`, and each column gives the count (`pseudonymized_levels`); the docs list the pseudonyms, which are synthetic labels. `--force-factor COL` is the one explicit opt-in: it keeps every real value of the column, even under a header that hints personal data or when values have personal-data shapes, and in that case it warns (`forced_copy`, counts only), so use it only for values that cannot identify anyone. `--force-type COL=TYPE` and `--org-code COL` only set the type and never skip these rules: an organisational code keeps its values except personal-data shapes (an e-mail address, phone number, SSN, URL or street address in it, even a building's, is never kept: `Homebound - 1427 Juniper Ridge Rd` gets a pseudonym; since a code is kept whatever its count, an address after a spaced dash counts there too, which in other columns and in headers is no address shape, so a gradebook's `Unit 1 - 3 Digit Place Value` or `Science - 3 Milky Way` stays as it is) and person names, a column whose header hints personal data keeps none of its values under either flag (each gets a pseudonym, with a `forced_type_values` warning), and a forced number type keeps the number rules below. **Person names inside organisational codes:** a section or homeroom code often carries its teacher's name. An organisational code holding a person's name in an explicit layout (`Garcia, Ana`, `Smith, J.`, `Ms. Garcia`, `Mr Smith`, `A. Garcia`, `Mrs. G`, a user name such as `jgarcia`, or a known given name next to a known surname such as `Ana Garcia`; found with the same checks as headers and paths above, so school, place, program and namesake names such as `Jesse H Jones High School`, `Rosa Parks Elementary` or `Mrs. Quenby's Academy` stay; and, since a false alarm here only costs a fake word, also what those checks leave to precision: any name of the lists before a comma and a given name or a capital initial, common surnames too (`Miller, Lisa`, `Miller, L`, `West, Ana`, `Le, Thanh`, `Wu, Lin`), a word off the lists before a known given name (`D'Souza, Priya`, `Ng, Wei`, `Vo, Minh`), a hyphenated given name (`Park, Ji-hoon`, `Ji-hoon Kim`), a known given name next to a common surname or a surname off the lists (`Lisa Miller`, `David Young`, `Mark Brown`, `Priya D'Souza`, `Fiona McAllister`, `lisa.miller`), any capitalised word after `Mr`, `Mrs`, `Ms.`, `Mx`, `Sra` ... (`Ms. Le`, `Mr. Ng`, `Ms. de la Cruz`, `Mrs. Van Der Berg`) and a distinctive surname with run-together initials (`Abernathy, RJ`); course words stay (`Biology, Honors`, `French, I`, `Math Block`), and `Ms` or `MS` without a period is a middle school as often as a title, so only a surname of the lists counts after it (`Ms Garcia`, `Ms Brown`; `MS Band`, `Ms Science 7`, `MS HOPE SQUAD` stay)) keeps its real text except the name part, the whole name with its middle initials, further given names and particles (`Thompson, Robert J`, `Mary K. Johnson`, `Garcia, Ana Maria L`), which gets a consistent fake name of the same layout, for example `ALG1-03 Garcia, Ana` -> `ALG1-03 Little, Guy` and `Algebra I - Ms. Okafor` -> `Algebra I - Ms. Fields`. Titles, suffixes and the course part stay real; each real name word gets one fake word for the whole run (a Faker name, never a word of any real text of the run) and an initial another letter, so the same real code becomes the same synthetic code in every file and column and joins on the code still match. The same name held by a value another column writes as it is (a level kept for its count under `Class`, `Homeroom`, `Advisory` or a pivoted `Period_3`, also inside a comma list: `ALG1-03 Garcia, Ana` as the items `ALG1-03 Garcia` and `Ana`) is replaced there too with the same fake name, the rest of that value staying real, so no column of the run keeps it and `Class` still joins `Section`; so is the same person's name in another layout or order, with fewer given names or with an initial (`Thompson, Robert`, `Robert Thompson`, `R. Thompson` for `Thompson, Robert J`; a bare surname stays). The report shows such values as `[pseudonymized N]` and counts them (`org_code_names_replaced`, also in `pseudonymized_levels`); the leak scan never excuses them, and the real name parts (`Garcia, Ana`, `Ms. Okafor`) and each name in either order (`Ana Garcia`) are indexed as sensitive text everywhere. Accents and letters such as `ß` or `Æ` are followed letter by letter (`Groß, Anna`); a code whose name cannot be located on its own characters (a name in a script the Latin lists cannot read) gets a whole same-shape pseudonym. Accepted residual risk: a bare single surname without a layout (`Homeroom` = `Garcia`) is no layout and stays, and so does a name the header and path check does not know (a name off its lists). `--force-factor COL` keeps the real codes. Accepted residual risk: a real name shared by at least `--min-cell` people in a column whose header names no person (a teacher's surname under `Homeroom`) is kept; `--pii-col COL=name` replaces it. A notes/comments/alert column holding numbers gets same-shape numbers, and so do numbers under a person header (staff numbers under `Teacher`, `Counselor` or `Case_Manager`; a plural such as `Students` is a count and stays a number), bare 10/11-digit phone numbers under a person, phone/contact (`SMS`, `Text`, `Home`, `Primary`) or notes header, and a number column holding a North American phone number under any header that names no ID, code, account or amount (`Ph`, `Number`, also one phone number typed among the scores of a `Response` column). No generated text holds a real phone number or SSN of the run, not even by chance: digits the tool draws (the random digits of an e-mail address or a note, a synthetic surname's digits next to a synthetic ID in a rebuilt e-mail address) are drawn again when they would spell one, and a rebuilt value that would hold one keeps an independently generated value, with a warning.
7. **Write and check**: the file is written in the source format and re-read; if its layout differs from the source the file FAILs (unless `--no-strict`). Excel workbooks are rebuilt fresh with the same sheet names, order and visibility (hidden sheets stay hidden), header row, cell types and number formats (literal text inside a number format, such as `"Prepared by J. Smith "0`, is masked to `"Xxxxxxxx xx X. Xxxxx "0`; units, currencies and symbols are kept), column widths, freeze panes and autofilter. Title and notes rows above or beside a table stay in place with same-shape placeholder text (an e-mail address, web address, phone number, SSN or street address inside it follows the rules of step 4, and no placeholder is a real text of the run; `--keep-titles` copies them verbatim), formulas become static values (SUM/COUNT/AVERAGE footers are recomputed from the synthetic rows), and extras such as comments, data validation, hyperlinks and named ranges are not copied (the report lists them). The header row is detected; `--header-row N` or `--range [SHEET!]A5:H200` sets it, and `--sheet NAME` reads one sheet. Parquet, Feather and Stata files keep their schema (column types, value labels, date formats, compression). Infinite numbers in a Parquet/Feather float column or a JSON number column (`inf`, `-inf`, `Infinity`) are written back at their exact counts like `NaN`, and the statistics leave them out. A pseudonymised category or value label is written as its pseudonym in its place; a category or value label that no row holds is left out (nothing ever checked its text) unless it is a vocabulary word (step 6), and Stata value labels that cannot be shown as values (duplicate or blank labels) are not written.

**Not preserved**: relationships between columns other than the structure above (group gaps, correlations, cross-column rules such as a join year being after an exam year unless declared under `rules:`), panel/time structure, aggregate suppression rules. This is not formal differential privacy.

## Options

Column options are repeatable (`--id-col a --id-col b`); there are no comma lists because headers may contain spaces and commas. A `COL` can be limited to one file as `relative/path.csv::COL` (or `book.xlsx::Sheet::COL`). `COL=VALUE` is split on the last `=`.

| Group | Options |
|---|---|
| Types | `--factor-max N` (20), `--force-factor COL`, `--force-text COL`, `--force-type COL=TYPE`, `--pii-col COL=SUBTYPE`, `--dayfirst COL`, `--date-cols COL`, `--date-format COL=FMT`, `--calendar COL`, `--na-value TOKEN`, `--decimal ,` |
| IDs and codes | `--id-col COL`, `--no-default-ids`, `--org-code COL` (keep real values), `--person-id COL` (synthesise), `--id-check luhn` |
| Floors | `--no-exact-extremes COL`, `--min-cell K` (10) |
| Columns | `--null COL` (write as all-missing), `--exclude COL` (drop; the schema changes) |
| Input | `--encoding`, `--delimiter`, `--sheet NAME`, `--header-row N`, `--range [SHEET!]A5:H200` (Excel table region; repeatable), `--include GLOB`, `--exclude-path GLOB`, `--keep-name TEXT` (a header, sheet, file or folder name flagged as personal data that is not; repeatable, one per name) |
| Run | `--seed INT`, `--config FILE.yaml`, `--force`, `--max-row-matches PCT`, `--no-strict`, `--keep-titles` (copy Excel title/notes rows and CSV footer notes verbatim), `-v` / `-q`, `--json` |

`TYPE` is a type name as shown by `inspect` (for example `FACTOR`, `INTEGER`, `FLOAT`, `IDENTIFIER`, `FREE_TEXT`). `--force`, `--max-row-matches`, `--no-strict` and `--keep-titles` apply to `run` only; `inspect` takes every other option. Without `--seed` a random seed is drawn, printed and recorded; the same seed, input and library versions give byte-identical output. A non-empty out dir or report dir needs `--force`. `--force` overwrites files but never deletes any: if a file that was written by an earlier run FAILs this time, its old copy stays in the out dir, and the console, the report and the out-dir `README.md` say it was not regenerated. The input folder, the out dir and the report dir must be three separate folders: none may be, contain or lie inside another, judged by where they really are (symlinks, junctions, short names and other aliases are resolved). An existing out dir or report dir may not hold a link that leads out of it, and an input folder or file that really lives in the out dir or report dir is refused. Contradictory column flags (for example `--force-factor X --force-text X`) are usage errors: nothing is written. An internal error FAILs its file with the error's class and code line (`ValueError at _reader.py:83`); `-v` adds its traceback as exception classes and code locations (file, line, function) only, never an exception's message, arguments, notes or variables, which may quote a cell. Warnings of the libraries the tool uses are printed with `-v` only, as their category and code location.

### Config file

Standing settings go in a YAML file passed with `--config`. Keys are the option names with `_` instead of `-`. Command-line values win over the file; repeatable options are combined. When the file and the command line both set how one column is treated, the command line wins, however either names the column: `--force-text x` replaces `force_factor: [x]`, and `--force-type data.csv::score=INTEGER` replaces `force_type: {score: FLOAT}` for that file. A command-line type option does not undo a `null` or `exclude` from the file.

```yaml
mode: fidelity
factor_max: 20
id_col: [student_number, state_id]
force_factor:
  - schools.csv::school_name
org_code: [site_code]
na_value: ["-9"]
null: [notes_internal]
seed: 20241001
structure:
  disable: [functional_dependencies]   # also derived_templates, composite_keys, cross_file_keys, sort_order, duplicate_rows
rules:
  - "KCSE <= Yr_JoinCampus"            # every file that has both columns
  - rule: "credits_earned <= credits_attempted"   # operators <=, <, >=, >
    file: sub/transcripts.csv                      # path relative to INPUT: this file only
```

`structure` and `rules` exist only in the config file. `structure: disable:` lists automatic structural relationships to turn off. A declared rule `A <= B` between two number or year columns, or two dates of the same kind (dates, date-times, times of day, durations, year-months, in any format), is built, not filtered: B becomes A plus a gap drawn from the gaps seen in the real data, so B's own distribution changes. Several rules on one column (`a <= c`, `b <= c`) are built together from the largest of their low columns, so all of them hold. A rule that cannot be built (a text column, a date against a date-time, a column constant within the ID against one that varies per row, a cycle, a rule the real data never satisfies) fails its file with the fix instead of being ignored, and every applied rule is re-checked on the output. The report suggests the rules that hold in every row, with the line to paste.

### Exit codes

| Code | Meaning |
|---|---|
| 0 | every tabular file was written (PASS or WARN) |
| 1 | unexpected error |
| 2 | usage or config error (bad option, refused folder) |
| 3 | one or more files FAILED and were not written (the report gives the fix) |

A file FAILs, for example, when it has no header row, holds nested values, has a header, sheet, file or folder name that holds personal data (shown redacted, never printed), has a table with no ID column and a column of keys of eight or more digits repeated across rows under a header the tool does not know (step 3; the fix names `--person-id`, `--id-col` or `--org-code` for that column, and no value is printed), has a zero-padded ID with no room left, differs in layout when re-read, or would put a real value in the output or the report (leak scan). The other files are still written. If the leak scan itself hits an internal error, only the file it concerns FAILs (its output is removed, and its details are left out of the report when they could not be checked); every other file is still checked and kept. An out-dir doc the scan cannot check is removed, and only an error that concerns no single file (on the run report itself) FAILs every file.

`inspect` uses the same codes: 3 means at least one file could not be read or profiled.
