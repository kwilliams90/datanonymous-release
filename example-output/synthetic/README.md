# SYNTHETIC DATA

> **SYNTHETIC DATA - NOT REAL RECORDS.** Every data file in this folder was generated by datanonymous. These generated fixtures are for invented-data and local testing. Personal-data fields are regenerated (row-number ID columns that run 1..n keep those numbers; listed below). Validate code compatibility separately; results computed from them are not real-data analysis. **FIDELITY MODE.** Exact source counts and extrema may survive. This folder is not an approved sharing package and these checks do not establish de-identification.

## How it was generated

- Generator: datanonymous 0.1.0 (Faker 40.40.0 pinned), seed 1. The same tool versions, the same input and `--seed 1` reproduce these files byte for byte.
- Each source file was profiled column by column and replaced by a synthetic copy with the same relative path and file name, the same header text and column order, the same number of rows (N rows in = N rows out) and the same file layout (encoding, delimiter, quoting, line endings, missing-value tokens).
- Every non-ID column was generated on its own from the source column's distribution: exact counts for categories, flags and missing-value tokens; interpolated values within the observed range for continuous numbers and dates; invented same-shape values for IDs, names, emails, phone numbers and other personal text; filler text for free text.
- These docs (README.md, DATA_DICTIONARY.md, schema.json) were computed from the synthetic files only.

## What IS preserved

- File names and relative paths, header text (exactly), column order and row counts.
- File layout: encoding, byte-order mark, delimiter, quoting, line endings, sheet/table structure, and the missing-value tokens (`NA`, blanks, ...) at their exact rates.
- Value formats: decimals, zero padding, date and time formats, boolean words, whitespace variants.
- Each column's own distribution: exact level counts for categories, booleans and ordered levels; observed values only for discrete integers; interpolated values within the observed range for continuous numbers and dates (the exact minimum and maximum appear, unless `--no-exact-extremes` turned this off for a column).
- Every source category level and missing-value token appears at least once (`rare_category_adjusted` marks columns where this changed a count).
- Replacement IDs keep their shape (width, zero padding, prefix) and avoid detected source IDs (except row-number values listed below); each synthetic ID has the row count of one real ID, and the same real ID gets the same synthetic ID in every file of the run, so joins between files work.
- Structure that holds in every source row: ID aliases and nesting, the same IDs across files (join and orphan rates), no repeated (ID, date) pairs, the sort order and the number of duplicate rows.
- Row-number ID columns (values exactly 1..n) keep their numbers and can retain assignment fingerprints: `student-scores.csv :: id`.
- Columns that are constant within an ID (such as gender or date of birth) stay constant within each synthetic ID.
- Whole-row patterns of missing values: columns that are blank together stay blank together (patterns held by fewer than 10 source rows are pooled).
- Structural rules applied in `student-scores.csv`: 1 derived template(s) (a column built from others).
- Structural rules applied in `students_data.csv`: 2 functional dependency(ies) (one column determines another).

## What is NOT preserved

- Relationships between columns: every non-ID column is generated independently of the others. Correlations (between scores), group differences (a score gap by gender or lunch status) and cross-column logic (a later year being >= an earlier year, a school name matching a school ID, an age plausible for a grade) do not hold, except the structural rules listed above.
- Panel and time structure: attendance spells, attributes that change across years and the order of events within an ID are not modelled.
- Cross-column rules that the report only suggests (they apply only when declared under `rules:` in `--config`), and aggregate suppression rules (small counts hidden in a source).
- Real IDs, names, emails, phone numbers, SSNs, addresses and free text: replaced by same-shape IDs, invented values or filler text. Real labels of high-cardinality text columns: replaced by invented labels with the same frequency profile.
- Rare real labels: a text value is kept only when it is a vocabulary word or shared by at least 10 people in the run (distinct IDs; identical rows count once in a table without IDs); any other value is written as a same-shape pseudonym with its exact count, the same pseudonym in every column and file.
- This is not formal differential privacy. The exact minimum and maximum of numeric and date columns are emitted, so a unique extreme value can equal one real person's value.
